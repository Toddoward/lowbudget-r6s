# 게임 데이터와 에디터

게임의 수치·배치·모델 연결은 모두 `data/` 폴더의 JSON 파일에 있습니다. 코드(`src/`)는 이 파일을 읽어서 동작하므로, 숫자를 바꾸려고 TypeScript를 열 필요가 없습니다. 파일은 빌드할 때 번들에 들어가서 실행 중 로딩 지연이 없습니다.

## 파일 구성

| 폴더 / 파일 | 한 파일 = | 내용 |
|---|---|---|
| `data/weapons/<id>.json` | 총 한 자루 | 피해·연사·탄창·반동·퍼짐·관통, 조준경 종류, 모델(`model.glb`)과 앵커(sight · lens · muzzle · grip · fore), GLB가 없을 때의 절차적 모양 |
| `data/optics/<id>.json` | 조준경 한 종류 | 배율, 아이릴리프(눈 거리), 조준 시 총 카메라 FOV, 레티클 모양·크기, 렌즈 크기·틴트 |
| `data/operators/<id>.json` | 오퍼레이터 한 명 | 진영·소속·역할, 아머·스피드, 장비(주무기·보조무기·가젯), 설명(한/영), 외형, 모델 |
| `data/gadgets/<id>.json` | 가젯 한 종류 | 사용 방식(도구·설치·투척·즉시), 설치 시간, 신관, 폭발 반경·피해, 가스, 사거리 등, 모델 |
| `data/rig/skeleton.json` | 3인칭 골격 | 골반·머리·어깨·고관절 위치, 팔 길이 |
| `data/rig/animation.json` | 3인칭 동작 | 자세 전환 속도, 걷기, 앉기·엎드리기, 달리기, 레펠, 손 위치, 재장전, 사망 (m, rad) |
| `data/rig/viewmodel.json` | 1인칭 | 비조준 FOV, 소총·권총·발사기·해머·장비를 드는 위치 |
| `data/maps/house/map.json` | 하우스 기본값 | 층 높이, 벽 높이, 지붕, 바깥 높이(도로·테라스·마당), 문·창 종류별 치수, 영역 |
| `data/maps/house/walls.json` | 벽 전체 | 층·방향·위치·재질(solid·soft·semi), 문·창, 재질이 다른 구간, 사선 외벽 |
| `data/maps/house/floors.json` | 바닥·지붕·해치 | 슬래브(구멍은 해치 ID나 `stairs:main`으로), 지붕 조각, 해치 |
| `data/maps/house/stairs.json` | 계단 | 계단, 층계참, 계단 구멍 |
| `data/maps/house/rooms.json` | 방 | 이름, 층, 영역, 목표 지점 |
| `data/maps/house/spawns.json` | 스폰·카메라 | 공격 스폰, 탈출 구역, CCTV |
| `data/maps/house/props.json` | 소품 | 가구·엄폐물: 위치, 크기, 재질(탄 관통), 색 |
| `data/schema/*.schema.json` | 스키마 | 각 필드의 한국어 이름·설명·단위·허용 값 (VS Code와 에디터가 사용) |

**좌표 규칙**
- **맵 (월드):** 미터 단위, +X 동쪽, +Y 위, +Z 남쪽 (북쪽 = −Z)입니다. 층은 B = −1, 1F = 0, 2F = 1입니다.
- **모델 (총 기준):** +X 오른쪽, +Y 위, −Z 총구 방향입니다. Blender 좌표로는 (x, −z, y)입니다.

**VS Code로 직접 고칠 때**
- 각 파일 첫 줄의 `$schema` 덕분에 자동완성과 설명이 뜨고, 잘못된 값에는 빨간 줄이 생깁니다.
- `note`·`group`은 사람이 읽는 메모라서 게임은 무시합니다.

## 에디터

```
npm install
npm run editor        # 브라우저에서 http://localhost:5173/editor/ 이 열림
```

**화면 구성**
- **왼쪽:** 파일 목록입니다.
- **가운데:** 3D 뷰 또는 평면도입니다.
- **오른쪽:** 값 편집 폼입니다. 필드 이름에 마우스를 올리면 설명이 보입니다.
- **조작:** `Ctrl+S` 저장, `Ctrl+Z` 되돌리기입니다.
- **게임 확인:** **▶ 게임 열기**로 게임 탭을 열어 두면, 저장할 때마다 그 탭이 자동으로 새로고침됩니다. 바뀐 내용을 바로 플레이해 볼 수 있습니다.

### 총기·조준경
- **모델·앵커:** 점(앵커)을 클릭하고 화살표를 끌어 옮깁니다. 오른쪽 폼의 숫자도 같이 바뀝니다.
- **정조준 (1인칭):** 오른쪽 위 작은 화면이 게임과 같은 정조준 화면입니다. 월드는 배율이 적용된 FOV로, 총은 조준경의 총 카메라 FOV로 그리고, 레티클은 렌즈 원 안에만 보입니다. 아래 안내에 카메라 위치(Blender 좌표)와 FOV가 나와서 Blender에서 같은 카메라를 놓을 수 있습니다.
- **비조준 (1인칭):** 들고 있는 자세입니다. `data/rig/viewmodel.json`에서 편집합니다.
- **3인칭:** 오퍼레이터가 총을 든 모습입니다. grip·fore 앵커가 손 위치입니다.
- **GLB 가져오기:** 오른쪽 점선 칸에 `.glb`를 끌어다 놓으면 `public/assets/models/handmade/weapon_<id>.glb`로 저장되고 `model.glb`에 연결됩니다.
  - 노드: `body` · `mag` (탄창) · `body_glow` (렌즈 캡, 3인칭에서만 보임)
  - Export: 트랜스폼 적용(Ctrl+A), +Y Up, Draco 끔, 버텍스 컬러

### 오퍼레이터·리그
- **자세 확인:** 위 버튼과 슬라이더로 서기·앉기·엎드리기·레펠, 상하 조준, 기울기, 걷기, 조준, 달리기, 재장전, 사망을 확인합니다.
- **골격 편집:** **리그 › skeleton**에서 관절을 끌어 옮기면 골격이 바뀝니다.
- **동작 값 편집:** **리그 › animation**의 값은 바꾸는 즉시 반영됩니다.
- **오퍼레이터 GLB 규칙:**
  - 발이 원점이고 −Z(Blender +Y)를 보며, 팔은 아래로 곧게 내린 자세로 통째로 모델링합니다.
  - 뼈대별 오브젝트 이름: `hips` `torso` `head` `armL` `armR` (위팔) `foreL` `foreR` (아래팔+손) `legL` `legR`
  - 게임이 각 부분을 골격의 관절 위치로 옮깁니다. 관절이 모델과 맞는지는 **리그 › skeleton**에서 확인합니다.

### 가젯
- **수치:** 오른쪽 폼에서 편집합니다.
- **모델:** GLB를 끌어다 놓으면 설치된 모습과 1인칭으로 든 모습에 함께 쓰입니다. 원점이 설치 지점이자 손에 쥐는 점입니다.

### 맵 (하우스)
- **보기:** B · 1F · 2F · 지붕 · 바깥(스폰·카메라) 평면도입니다.
- **선택·이동:** 클릭으로 선택하면 오른쪽에 그 요소만 나옵니다.
  - 드래그로 옮기고, 벽은 끝을 잡으면 길이를 바꿉니다. 문·창은 벽을 따라 움직입니다.
  - 화살표 키: 0.05 m씩 이동 (Shift ×10)
  - Delete: 삭제, Ctrl+D: 복제
  - 휠: 확대, 오른쪽 드래그: 화면 이동
- **추가:** **＋ 소품 / ＋ 벽 / ＋ 문·창 (선택한 벽에)** 버튼을 씁니다.
- **3D 확인:** 저장하면 열린 게임 탭이 새로고침되니 거기서 확인합니다. 플레이 중 QA 자유 시점(`?qa`)도 쓸 수 있습니다.

## 검증 (자동)

```
npm test
```

- **`data.test.ts`:** 모든 파일이 스키마에 맞는지 확인합니다. 파일 간 연결도 검사합니다: 장비의 총·가젯, 총의 조준경, 모델 파일이 실제로 있는지.
- **`handmade.test.ts`:** 직접 만든 총 모델의 형식(압축 없음, 트랜스폼 적용, 노드 이름, 버텍스 컬러)을 확인합니다. 렌즈 캡, 앵커가 모델 위에 있는지(조준선이 비어 있음, 렌즈 원이 통 안, 총구가 총열 끝)도 봅니다.
- **맵 테스트:** `walk`·`zfight`·`terrain`·`props` 등이 맵을 바꿨을 때 이동 경로, 스폰 주변 공간, 겹침을 검사합니다.

CI도 같은 테스트를 돌리고, 통과해야만 배포됩니다.
